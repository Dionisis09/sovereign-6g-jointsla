# Preregistered pressure sweep and factorial mechanism analysis

Written before new simulation outcomes. MEDIUM: 10 nodes, 40 services, 100 × 0.1 s. Controllers, routing, resource semantics, original service definitions, deadlines, network, hardware profiles and assignment remain unchanged. No re-profiling, tuning or optional extensions selected from favorable results.

Pressure loads: 0.50, 0.75, 1.00, 1.25, 1.50, 1.75, 2.00; paired seeds 1–30. 1.00 uses the exact DIRECT tape. Other loads use marked thinning of original compound-Poisson clusters (m<1) or independent cluster superposition at (m−1)λ (m>1), conditional on original frozen noise and burst schedule. No base service rate/reservation or initial-placement changes. Original RNG streams are untouched; independent keyed adapter streams generate marks, extra arrivals and work. Expected service/tier/class proportions are preserved exactly; realized request proportions fluctuate as compound Poisson sampling requires. Shared marks across low loads and shared extra-stream seeds across high loads; no claim of perfect request nesting across high loads.

PS1: descriptive low-load advantage, examined at 0.50/0.75. PS2: trend in paired SLA difference, a within-seed OLS slope across all seven loads with paired-seed bootstrap CI (exploratory, not a monotonicity guarantee). PS3: exploratory mean sign reversal; supported crossover requires opposite mean signs at observed grid points AND opposite supported paired directions. No interpolated exact threshold. PS4: lower mean replicas, VRAM and actions at ≥4 of 7 loads (descriptive). PS5: exact per-pair tape hashes and frozen profile/source checks.

Statistics: reuse frozen 10,000 paired-seed percentile bootstrap, seed 73001, Wilcoxon two-sided with differences rounded to 12 decimals and frozen zero/tie rules; positive RBC favors JointSLA, Delta=Joint−SLA. Holm families: primary SLA+p95 across 7 loads (14); secondary mean+p99 across 7 loads (14); tier SLA across 7×3 (21, exploratory); model-class SLA across 7×3 (21, exploratory). No equivalence margin. Operating-envelope labels: statistically supported SLA-aware-favored or JointSLA-favored by primary breach CI+Holm; otherwise 'approximately competitive / statistically unresolved', explicitly not evidence of equivalence. Tail disagreement disclosed. Seed arithmetic means, sample SD; no request pseudoreplication.

D0–D7: full 2³ factorial with execution E, memory V, cold C flags: D0=000,D1=100,D2=010,D3=001,D4=110,D5=101,D6=011,D7=111. Seeds 1–10 only; all use identical original 1× traffic. E changes class worker stage times and population-weighted global stage estimator; V changes only service/application memory reservation; C changes class lifecycle readiness and weighted global cold estimate. No other fields change. D0 uniform synthetic physics, D7 exact DIRECT. Report paired descriptive differences and factorial contrasts including interactions; no confirmatory significance at N=10. Default no 30-seed decomposition extension: 30-seed D7 already exists; additional extension only if a specific uncertainty warrants it, never solely a favorable factor.

Diagnostic definitions fixed before results: request queue=service+node waits; average/peak waiting queues are slot-end samples. Observation-only decision-start snapshots record per-service waiting/ready/allocated replicas and per-node free physical tokens/reservations without extra SimPy events or controller inputs. 'No feasible scale-out' means no service below max replicas and outside cooldown fits any CPU/VRAM/bandwidth reservation; separate pure-capacity flag retained. Contention at routing: selected candidate has positive resource-wait estimate, or busy, or nonempty queue; baseline has no explicit routing choices, so reported contention uses positive realized node/service wait as a separate shared request measure, never equated to routing contention. Resource saturation uses unchanged 80% threshold. Completion throughput counts actual completion times within horizon; arrival-cohort completions including drain exported separately.

Burst recovery: per-service known exogenous burst starts are used ONLY retrospectively. Preburst ready replicas/waiting queue from slot before start (or slot 0). Queue threshold=max(preburst waiting,1); recovery first decision-start sample at/after burst end and before next burst with queue≤threshold. Censored if absent; do not impute recovery time. Record first scale-out at/after start before next burst, all actual cold readiness intervals, queue growth during burst, arrival-cohort SLA in start-to-recovery/next-burst window and horizon-censored requests. Decision timestamps are slot start, action records use their exact simulated time. Representative seed selection at DIRECT: sort Delta_SLA ascending then seed; best first, median lower-central index, worst last. Show all selected examples with labels; no cherry-picked seed.

Full order: protected hashes/profile verification → existing tests → exact DIRECT seeds 1/2/3 rerun → sweep pilot extremes on seeds 1/2/3 → config/source freeze → full sweep → crossover analysis → 10-seed factorial → mechanism analysis. Pilot tests feasibility, not tuning. All outcome rows, capacity ledgers and routing choices audited and re-read from exports. Old result trees remain byte-identical.
