# JointSLA-v2 preregistration

One candidate only. Design derived from previously verified seeds1–30 and mechanism analysis; development uses101–105 at0.5/1/2× solely for correctness, unit scale, action/capacity feasibility and stable runtime. No grid search. Held-out seeds31–60 are not generated, simulated, read or analyzed before a successful freeze. No held-out 1.5× run scheduled. ## Units and one fixed design

Slot Δ=.1 seconds. Per-service readiness R=cold_start_slots×Δ uses the unchanged hardware class mapping. History W=max_s(cold_start_slots)=5 complete prior slots. Recent λ=sum(observed prior-slot arrivals)/(observed slots×Δ), requests/s; initial empty history is zero, not hidden base/future traffic. No scheduled burst mask enters controller inputs.

L in seconds is the minimum finite positive current ready-candidate cycle_ms/1000 (v1’s nominal/past-completion observable). If none ready, use minimum capacity-feasible nominal candidate cycle. It includes CPU/GPU/network/resource delay and excludes service queue waiting; it is an estimated serial replica cycle, not measured global GPU capacity. Slack h=max(deadline_seconds−L,0).

Current FIFO backlog q requests must fit ready capacity during deadline slack: queue demand qL/h replica-equivalents. During cold recovery, current backlog and λR arrivals must fit ready capacity through R+h: recovery demand (q+λR)L/(R+h). Their maximum guards both immediate backlog and replenishment exposure. Larger R increases the recovery term when it dominates the immediate term, so cold exposure cannot reduce the unbounded requirement at fixed λ,q,L,h. This is a conservative causal fluid estimate, not a guarantee or forecasting model. If h≤0 and demand exists, require the existing max_replicas; if no finite feasible L, require max_replicas. Expose unattainable deficit rather than exceeding capacity.

Tier multiplier f: Bronze1, Silver sqrt(G), Gold G. Single interpretable fixed design constant G=1.5; base H=1, Gold ready floor2, Silver/Bronze floor1. Required=min(existing max_replicas=3,max(tier floor,ceil(f×max(queue demand,recovery demand)))). W is derived, not searched. Gold floor2 retains one additional serial pipeline while a cold replica is unavailable; it does not allow unlimited placement.

Controller: call frozen v1 joint_actions exactly once. Reject only selected scale_down proposals for which ready_after_removal<required. Preserve all v1 routing/scoring, other proposed actions and their order. A floor guard alone cannot establish Gold floor2 from original one-warm initial placements: therefore allow Gold-only capacity repair when ready+already pending replicas<required, subject to original cooldown/max replica/admission rules. Prioritize largest Gold deficit, then original SVRS, recent observed λ, service ID. Rank feasible targets by existing deployment_quality and its existing weights/cold overhead, preserving global frozen estimator. Fill at most the original two actions/slot; Gold repair precedes other retained v1 actions and one action/service. No Silver/Bronze autonomous scale-out. No extra action budget, initial allocation or lifecycle changes. Original controller estimates remain global; new retention reads real class readiness only.

## Engineering acceptance before freeze

Single candidate accepted only if all tests/request accounting/capacity/routing checks pass, actions≤2 every slot, max replicas≤3 every service, finite positive times, maximum per-run wall≤600s, RSS≤4096MiB, drain≤120s, and v2 per-run mean decision step<10ms on development. Gold guard invariants must hold when a scale-down is admitted; capacity-infeasible Gold deficits are recorded and never waived. Development does not select by held-out-looking SLA/resource outcomes. If engineering correctness fails, repair only implementation/units or semantics-safe optimization before freeze; no hyperparameter search.

## Held-out design and statistics

Two regimes1×/2×,30 paired seeds31–60, policies SLA-aware/v1/v2:180 simulations. Same unchanged hardware-grounded traffic adapter and hashes for each seed/load across all policies. Original simulator, profiles, service deadlines, node resources, network, MJO, v1 and request accounting are protected by hashes. Additional telemetry is read-only; original worker and finite resources are inherited unmodified. Seed isolation guard executes before workload generation; every generated seed logged with phase/freeze hash.

Frozen statistical helpers: paired bootstrap10000, percentile95%CI, RNG73001; Wilcoxon two-sided rounded12decimals, same zero/tie rules; positive RBC favors v2, Δ=v2−comparator. Primary Holm families separately v2-v1 (SLA,Gold,p95 across two loads =6) and v2-SLA-aware (6). Secondary separate families per comparator: mean,p99,Silver,Bronze,average replicas,average VRAM,total actions across two loads =14. Class effects descriptive unless labeled exploratory; no extra confirmatory family. Paired resource ratios and latency ratios use bootstrap of seed means, not request resampling.
