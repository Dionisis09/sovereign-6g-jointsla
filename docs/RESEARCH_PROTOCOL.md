# Research protocol and evidence boundary

Phase 1 is a deterministic **simulation** demonstration. Seed, scenario version, policy version, bundle schema version, candidate source and rule version must accompany each run. Forecasts are hand-written rules, not trained or calibrated models. Simulated SLO success is not hardware validation or a measured probability. The live JointSLA prototype and frozen research results are separate evidence streams.

For Phase 2, freeze scenario-group and seed-disjoint train/validation/test partitions before model selection. Label first future breach only while currently healthy; retain right-censored TTV observations. Evaluate breach classifier calibration and Brier score, censored TTV, action-conditioned TTR, PostSLA and downstream decisions. Compare no-op, SLA-aware, existing JointSLA and recoverability-aware variants on identical tapes and repeated seeds. Record data/config/code hashes, failures and negative findings. Do not tune thresholds on holdout data or infer hardware gains from synthetic results.

## Phase 2 preregistration (before data generation)

`PHASE2_SPLITS.json` freezes five scenario families, a 12-second horizon and seed-disjoint train 0–59, validation 60–79, and test 80–99 groups. Each seed/family pair contributes one initially healthy snapshot, so windows do not overlap. The scenario family and future event schedule are metadata, never model features. Seeds are grouped across all families. A no-breach episode is administratively right-censored at 12 seconds, not labeled as TTV=0. The binary target is breach within the fully observed 12-second horizon.

The preregistered feature set is current queue, arrival rate, cycle time, network time, SLO and observed headroom. Models: constant-prior and rule-threshold warning baselines, logistic breach model with sigmoid calibration on validation only, discrete-time logistic hazard for TTV, action-conditioned q90 TTR regression, and calibrated action-conditioned PostSLA classification. A fitted model is loaded only from a trusted local artifact with a manifest hash. No future event, split label, scenario family, seed or outcome enters a feature matrix. The test partition is evaluated once after choices are fixed.

Protocol amendment before test evaluation: `scikit-learn==1.9.1` was installed but a compiled `_cython_blas` DLL was blocked by Windows Application Control at import. The estimator implementation is therefore NumPy logistic regression with validation-only sigmoid scaling and NumPy linear q90 quantile regression. Coefficients are stored as checked JSON instead of pickle. Split seeds, feature set, targets, horizon and metrics are unchanged. The holdout test labels had not been inspected or evaluated when this amendment was made. The automated warning threshold is 0.3 and required PostSLA probability is 0.8; both are fixed before test evaluation.

Metrics: breach Brier, PR-AUC, AUROC when both classes exist, ECE; TTV integrated Brier through 12 seconds and observed-event MAE/pinball (not censor-aware on their own); TTR q90 pinball and empirical upper coverage; PostSLA Brier, PR-AUC and ECE; selected-action count and simulated SLO outcomes. Quantile names indicate empirical targets, not guaranteed safety. Calibration and coverage are reported, not assumed. All evidence is `SIMULATION_ONLY`.

Optional Jev, agentic and RL arms require separate implementation and ablations. All candidate proposals pass the same independent feasibility and authorization gate.

## Phase 3 evaluation boundary

The Phase 3 fixture set checks English/Greek labeled intents, missing/extra/impossible fields, instruction overrides, mocked structured Responses payloads and outage, tenant-filtered knowledge retrieval, separate approval, restart, denial, duplicate calls and schema migration. This is functional correctness evidence, not a measured language-understanding benchmark. Lexical retrieval is deliberately small; cited snippets are local versioned data and never treated as policy authority. No prompt, KB or LLM result may bypass deterministic action gates. No external LLM call is made during tests or the offline demo. Live quality, cost, latency and residency need a separately approved evaluation before claims.

## Phase 4 preregistration before fixture evaluation

Use the existing frozen Phase 2 seed-disjoint test partition (seeds 80–99, five families, 100 initial snapshots) and the unchanged action outcome table. No threshold or question wording is tuned on those test labels. Compare (A) trained classic ML, (B) deterministic fixture judgments alone, and (C) classic ML plus fixture advisory, on the same snapshots. The fixture is **not a Jev model**; its answers are synthetic rule proxies to verify the adapter and comparison harness. Real Jev-only and hybrid accuracy remains unmeasured until authorized live calls and a separately frozen evaluation. Primary integration metrics are advisory availability, review flags, malformed/outage fallback, selected action agreement and simulated downstream SLO on matched episodes. Report breach Brier only for arms with a numeric warning; do not turn Choice bins into calibrated seconds. Report latency and token usage from mocked/live responses separately and do not infer live cost from fixture values. Runtime policy selection must remain unchanged in the advisory-only comparison; an OFF/ON benefit claim would require a separately preregistered policy intervention.

## Phase 6 validation boundary

Offline tests exercise contract and failure paths with HTTPX MockTransport and must label receipts and GPU samples as mocks. The local canary success/rollback trace is simulated. A later cluster study must record Kubernetes/HAMi versions, namespace/RBAC and admission configuration, Deployment UID/resourceVersion, GPU type, exporter provenance, request/response audit, rollout readiness, observed service p95, rollback state and repeatable seed/workload schedule before making any hardware or transfer claim. A successful API-server dry-run alone is not an outcome label or evidence of available GPU capacity. No Phase 2/4 frozen result is retuned or overwritten by this validation.

## Phase 7 preregistration and result boundary

`PHASE7_PROTOCOL.json` fixes the one-step masked policy-gradient experiment before the Phase 7 test run: Phase 2 train/validation/test seed groups, current-only features, hard-mask profile, migration denial, three fixture reward proposals, five policy RNG seeds, epochs/learning rate, common validation selection metric, no-op/SLA-threshold/JointSLA baselines and paired episode-seed bootstrap. The full synthetic counterfactual action table permits matched toy evaluation; it is not logged real-world off-policy data. Validation alone selects the proposal. Test seeds 80–99 are reused from Phases 2/4 and therefore are not a fresh holdout. A mechanical noninferiority gate can only create an offline review candidate; manual review is required and v1 is rejected for lack of incremental benefit. No experiment output can load into runtime policy automatically.
